# A4 모눈종이 편집·인쇄 웹앱 구현 계획

## 기준과 완료 조건

원본 설계: [개정 5](../../2026-10-20-a4-grid-paper-webapp-design.md). 이 계획은 구현 순서와 검증 방법을 구체화한다. 앱 코드는 아직 작성하지 않는다. 원본 설계의 수치·기능 범위·출력 제약을 유지한다.

현재 확인된 기반은 설계 문서뿐이며 package.json이나 앱 모듈은 없다. 따라서 아래 경로는 기존 코드 참조가 아닌 신규 생성 예정 경로다. React/Konva/jsPDF 없이 Vite·TypeScript·HTML/CSS와 브라우저 API를 사용한다. 버전과 실행 환경은 구현 시작 시 확인하고 잠금 파일로 고정한다.

첫 결과물은 편집기가 아니라 한글·줄바꿈·A4 단일 페이지 출력을 확인하는 검증 페이지다. U1 통과 전에는 편집기 본체 작업으로 진행하지 않는다. 이후 U2 → U3 → U4 → U5 → U6 순서로 진행한다. 초기 검증의 HTML/SVG/CSS는 본체에서 그대로 공유해 검증 결과가 버려지지 않게 한다.

## U1 시작 전 버전 관리 준비

원격 저장소: [huynsolm/grid](https://github.com/huynsolm/grid), Git 주소는 `https://github.com/huynsolm/grid.git`이다. 구현 착수 시 원격 저장소의 기존 브랜치·커밋 유무를 먼저 확인한다. 원격이 비어 있으면 로컬 초기화 후 이 주소를 origin으로 연결한다. 기존 이력이 있으면 해당 이력을 기준으로 로컬 작업을 연결하고 기존 설계서·계획서를 보존한다. 독립적인 초기 이력을 강제로 덮어쓰거나 force push하지 않는다. 기존 origin이 다른 주소라면 자동 교체하지 않고 불일치를 알린다.

현재 작업 폴더는 git 저장소가 아니므로 구현 착수 시 먼저 `git init`을 수행하고 `.gitignore`를 작성한다. 이번 계획 수정 중에는 실행하지 않는다. 최소 실행 기반은 U1에 유지하며 별도 U0은 만들지 않는다.

`.gitignore`는 `node_modules/`, `dist/`, `.vite/`, 테스트 임시 산출물과 `docs/qa/pdfs/`, `docs/qa/tmp/`의 임시 PDF를 제외한다. 확장자 전체를 무조건 제외하지 않고 증거 파일 경로를 구분한다. PDF 원본은 로컬 증거로 보관하고 측정 결과와 상대 경로를 QA 문서에 커밋한다. 저장소 복제만으로 PDF 원본이 복원되지 않는다는 점을 기록한다.

첫 커밋에는 기존 설계서 `2026-10-20-a4-grid-paper-webapp-design.md`, 이 계획서, `.gitignore`를 포함한다. 기존 문서를 첫 커밋에서 누락하지 않으며 무관한 HTML 파일은 일괄 추가하지 않는다.

U1~U6의 공통 완료 조건은 해당 단위의 검증 통과, 결과 기록, 관련 변경 커밋 완료다. 각 단위 완료 시 커밋을 남기고 커밋 메시지에 U 번호를 포함한다. U1의 사용자 결과 대기 중 작업 저장용 커밋은 가능하지만 완료 커밋이나 U2 진입으로 간주하지 않는다. 커밋 불가 시 사유를 남기고 단위 완료로 선언하지 않는다.

## 구현 단위

### U1. 인쇄 검증 페이지와 최소 실행 기반

대상: `package.json`, `index.html`, `src/main.ts`, `src/validation/print-fixture.ts`, `src/paper/render.ts`, `src/paper/paper.css`, `src/print/print.css`, `tests/browser/print-fixture.spec.ts`, `scripts/qa/measure_pdf.py`, `tests/qa/test_measure_pdf.py`, `requirements-qa.txt`, `docs/qa/print-validation.md`.

목적: 브라우저 인쇄 방식이 원본 6·10·11절의 한글과 실측 요구를 만족하는지 먼저 확인한다. 이 단계의 시스템 폰트·직접 선택한 테스트 폰트·출력 모드 전환은 검증용 최소 기능이며 완성 편집 UI를 만들지 않는다. 업로드 폰트 검증은 이용 권한이 확인된 로컬 테스트 파일을 사용하고 권한 확인 전에는 배포물에 포함하지 않는다.

검증 내용:

- mm 크기 용지, SVG 모눈, 고정 폭 HTML 텍스트와 화면/인쇄 공통 스타일을 만든다. 한글/영문 혼합, 긴 문자열, 개행·빈 줄, 100mm 기준선, 안전 영역 하단의 텍스트를 고정 사례로 둔다.
- 실제 Chrome/Edge 인쇄 대화상자에서 ‘PDF로 저장’을 실행하는 주체는 사용자다. 세로/가로 × 여백 0/5/20mm의 사례별 파일을 사용자가 저장한다. 에이전트의 자동 PDF 생성으로 대체하지 않는다.
- 저장 위치는 `docs/qa/pdfs/u1/`이며 파일명은 `{browser}-{orientation}-margin{mm}-{case}-r{run}.pdf`로 통일한다. browser는 chrome/edge, orientation은 portrait/landscape, case는 테스트 문구·폰트·출력 모드를 식별하는 고정 사례 id, run은 재검증 번호다. 예: `chrome-portrait-margin5-system-with-text-r1.pdf`.
- 사용자는 결과 파일을 위 경로에 두거나 제공하고, 사례별 브라우저 전체 버전·OS 버전·화면 확대 배율·인쇄 배율·A4/방향·여백·머리글/바닥글·페이지 맞춤 설정을 알려 준다. 에이전트는 파일명과 메타데이터를 `docs/qa/print-validation.md`에 기록한다. 사용자 결과 파일이 제공되기 전까지 U1은 대기 상태이며 U2로 넘어가지 않는다.
- PDF 페이지 크기는 해당 방향의 A4이고 페이지 수는 1이어야 한다. 화면과 PDF의 줄 수·줄바꿈·상대 위치를 대조한다. 정량 판정은 MediaBox 환산·회전 반영 용지 치수의 축별 절대 오차 0.2mm 이하, 100mm 기준선 길이의 절대 오차 0.1mm 이하로 분리하며 실물 프린터 오차와 구분한다. 2026-10-21에 용지 치수 허용 오차만 기존 0.1mm에서 변경했다.
- PDF 정량 측정 도구는 Python `pdfplumber`로 정하고 QA 전용 의존성을 `requirements-qa.txt`에 버전 고정한다. 이는 앱의 PDF 생성 엔진이 아니라 사용자가 저장한 결과 파일의 검사 도구다. 측정 절차는 `scripts/qa/measure_pdf.py`와 `docs/qa/print-validation.md`에 명시한다.
- 측정 절차: 파일별 페이지 수와 각 페이지의 MediaBox를 읽고 두 축의 길이를 구한다. PDF 사용자 단위가 기본값인지 확인하고 UserUnit이 있으면 반영해 pt→mm를 25.4/72로 환산한다. 페이지 회전도 반영한 표시 방향 치수를 A4 210×297mm 또는 297×210mm와 대조한다. 각 축의 절대 오차가 0.2mm 이하이고 페이지 수가 1이어야 한다. 기준선 허용 오차 0.1mm는 독립적으로 유지하며 측정 JSON에는 두 허용값을 각각 기록한다.
- 100mm 기준선은 모눈과 구별되는 검증용 벡터 선분으로 두고 위치/색을 고정 사례에 기록한다. 파서의 선분 또는 경로 좌표에서 해당 선의 두 끝점을 식별해 변환된 좌표 간 길이를 mm로 구한다. 선 굵기 바깥쪽이 아닌 중심선 끝점 사이를 측정하며 |측정 길이−100mm| ≤ 0.1mm를 적용한다. 선분이 래스터화되거나 식별되지 않으면 통과로 추정하지 않고 미검증으로 기록한다.
- `docs/qa/print-validation.md`에는 사례 id·PDF 상대 경로·사용자 수행 여부·위 환경/설정·파서 버전·페이지 수·MediaBox/UserUnit/회전·환산 치수와 축별 오차·기준선 끝점/길이/오차·판정·채택 CSS와 여유·하단 잘림/줄바꿈 육안 결과를 남긴다. 파서 측정은 에이전트가 수행하며 치수 정상/오차 초과/여러 페이지의 알려진 PDF로 측정 계산을 검사한다. 파서 또는 실행 환경이 없으면 미검증으로 남기고 U1 완료로 선언하지 않는다.
- 우선 여유 0mm로 검사한다. 빈 페이지가 재현될 때만 원본 6절의 래퍼 완화·최대 0.1mm 여유를 적용한다. 내부 용지를 축소하지 않고 하단 경계를 재검증한다. 최하단 선/텍스트가 유실되면 통과로 처리하지 않는다.
- 자동 브라우저 검사는 print 매체에서 UI 숨김·공통 DOM 유지·A4 스타일·출력 모드만 확인한다. 자동화된 PDF 출력이나 화면 캡처만으로 실제 대화상자 검사를 대체하지 않는다.

통과 조건: 사용자가 제공한 실제 대화상자 PDF를 확보하고 두 브라우저에서 위 필수 사례가 통과하고 `docs/qa/print-validation.md`에 채택 CSS·PDF 증거 경로·미검증 항목이 기록된다. 도구 또는 브라우저 부재로 확인하지 못한 항목은 미검증으로 남기며 U1 완료로 선언하지 않는다. 재현 실패가 남으면 출력 방식의 변경은 별도 설계 변경으로 다룬다. 검증 기록과 U1 관련 변경의 커밋까지 완료해야 U2로 진행한다.

### U2. 문서 모델·상태 저장소·명령 실행 골격·mm 기하·모눈 설정

의존: U1 통과. 대상: `src/model/document.ts`, `src/model/validate.ts`, `src/state/document-store.ts`, `src/history/commands.ts`, `src/paper/geometry.ts`, `src/paper/grid.ts`, `src/ui/page-panel.ts`, `tests/unit/document.test.ts`, `tests/unit/document-store.test.ts`, `tests/unit/commands.test.ts`, `tests/unit/geometry.test.ts`, `tests/unit/grid.test.ts`.

원본 3·4·9절을 구현한다. 모델 version 1과 DB 스키마 버전은 독립적이다. 원본 데이터는 mm/pt로 유지하고 선택·확대·측정 높이는 UI 상태로 둔다. SVG 강조선은 기본선과 중복하지 않으며 부분 칸을 안내한다. 시스템 기본 fontId는 항상 유효하다.

문서 상태 저장소와 명령 실행 골격을 이 단계에서 만든다. 모든 문서 변경은 명령 실행 경로에서 검증한 뒤 저장소에 반영하고 구독자에게 알린다. UI·렌더러·저장 모듈이 공유 문서를 직접 변경하지 못하게 한다. 초기 문서 설정과 복원도 명시적인 초기화/복원 명령으로 처리하며 사용자 편집 이력과 구분한다. 이후 편집이 재작업 없이 붙을 수 있도록 변경 전후 값과 작업 그룹 식별 정보를 전달하는 경계를 정한다. 최근 100개 보관·그룹화 확정·Redo 제거·폰트 이력 참조 정책은 U5에서 연결한다.

검증: 세로/가로 A4, 간격 1/2/5/10mm, 여백 범위, 강조선 0/5/10, 기본선 굵기/불투명도 경계, 287mm 영역의 10mm 간격 끝 7mm를 확인한다. 잘못된 색·NaN·범위 밖 숫자·중복 id·미지원 모델 버전은 저장 복원 검증에서 거부한다. 방향 변경이 원본 좌표나 글자를 자동 축소하지 않아야 한다. 유효 명령은 한 번만 상태를 반영·통지하고 잘못된 명령은 문서와 구독 통지를 바꾸지 않아야 한다. 직접 상태 변조 차단, 초기화/복원 명령 구분, 변경 전후 값·그룹 정보 전달과 용지/모눈 설정 UI의 명령 경유를 검사한다.

### U3. 텍스트 편집·IME·이동·폭 조절

의존: U2. 대상: `src/editor/controller.ts`, `src/editor/text-editor.ts`, `src/editor/measure.ts`, `src/ui/text-panel.ts`, `tests/unit/snap.test.ts`, `tests/browser/text-editing.spec.ts`, `tests/browser/geometry.spec.ts`.

원본 4·5절을 구현한다. 이동·폭 조절·텍스트 편집·속성 변경과 추가·복제·삭제는 모두 U2 명령 실행 골격을 통해 문서를 바꾼다. 드래그/입력 중 미리보기는 런타임 초안으로 두고 완료 시 문서 변경 명령으로 확정한다. 단일 클릭 선택, 더블클릭/Enter 편집, 추가·복제·삭제, 숫자 위치/폭, 정렬·색·크기·줄 간격을 제공한다. textarea와 표시 div는 폰트와 폭 관련 스타일을 공유하고 텍스트는 textContent로 렌더링한다. 입력 초안도 현재 표시 div에 동기 반영해 인쇄 시 화면과 다른 오래된 내용이 남지 않게 한다. 조합 중 앱 출력 요청은 조합 완료를 기다리게 하며 강제 확정하지 않는다.

측정은 원본 4절의 offsetHeight와 경계 정밀 재확인을 공통 함수로 처리한다. 글씨 레이어가 빈 모눈 모드에서 숨겨져 측정 불가능하면 이전 높이를 신뢰하지 않고, 글씨 포함으로 복귀할 때 재측정한 후 준비 상태를 갱신한다.

검증: 각 편집 동작의 명령 경유, 취소된 초안의 문서 미반영, 확정 시 변경 전후 값과 그룹 정보 전달을 확인한다. 50/100/200% 배율에서 같은 드래그·높이·안전 경계, 스냅 최소 폭 10mm·Alt 해제·숫자 입력 예외를 검사한다. 긴 혼합 문자열·빈 줄·HTML 붙여넣기·Ctrl+Enter·선택/입력 단축키 구분을 확인한다. 조합 이벤트 자동 검사 외에 실제 한글 IME로 확정·개행·삭제를 수동 검증한다. 넘침 시 글씨 포함 출력 차단·빈 모눈 허용, 여백/폰트 변경 후 재검증을 확인한다.

### U4. 폰트와 단일 문서 저장·복원

의존: U3. 대상: `src/fonts/registry.ts`, `src/fonts/upload.ts`, `src/storage/database.ts`, `src/storage/autosave.ts`, `tests/unit/font-policy.test.ts`, `tests/browser/storage.spec.ts`, `tests/browser/fonts.spec.ts`.

원본 7·8절을 구현한다. system-sans를 DB와 무관하게 먼저 구성한다. 업로드는 허용 확장자·20MiB 제한·FontFace 로드를 검사하고 고유 family와 400만 제공한다. 누락 fontId의 재업로드는 사용자가 해당 항목의 복구 동작을 선택할 때 원래 id를 유지한다. 사용 중 face 로딩과 document.fonts.ready를 모두 확인한다.

U4에서는 폰트 삭제 UI를 만들지 않는다. 현재 문서만 확인하는 임시 삭제 경로도 제공하지 않는다. 실제 삭제 기능은 U5에서 Undo/Redo 이력 참조 검사와 함께 연결한다. 폰트 적용·대체와 복원 등 문서 변경은 U2의 명령 경로를 사용한다.

DB는 `documents`의 `current` 한 문서와 `fonts`의 업로드 Blob/메타데이터를 저장한다. 폰트 저장 성공 후 참조를 반영한다. 저장 요청은 순서대로 처리해 느린 과거 저장이 최신 문서를 덮어쓰지 않게 하며, 변경 완료 후 500ms 디바운스를 적용한다. 복원 오류가 있으면 손상 데이터를 자동으로 빈 문서로 덮어쓰지 않고 메모리 편집과 실패 안내를 제공한다.

검증: 폰트 삭제 UI와 실행 경로가 아직 제공되지 않는지 확인한다. 최초 실행에 업로드/번들이 없어도 편집·복원 가능, 같은 이름 파일 충돌 없음, 700→400 정책, 20MiB 경계·손상 파일·누락 Blob·저장소 차단/용량 초과를 확인한다. 새로고침 후 줄바꿈 재현, 최신 저장 유지, 명시적 시스템 폰트 대체와 원래 id 복구를 검사한다. 추가 번들 폰트는 권한·출처·버전·고지 확인을 통과한 파일만 포함하며 목록이 비어도 출시 기능은 유지한다.

### U5. 명령 이력·출력 준비·전체 UI 연결

의존: U4. 대상: `src/history/policy.ts`, `src/fonts/delete.ts`, `src/ui/font-panel.ts`, `src/print/controller.ts`, `src/ui/toolbar.ts`, `src/ui/status.ts`, `tests/unit/history.test.ts`, `tests/browser/print-gate.spec.ts`, `tests/browser/font-history.spec.ts`.

원본 6·7·8절을 연결한다. 명령 실행 골격은 U2의 것을 재사용하며 이 단계에서 새로 도입하지 않는다. 명령 계층 관련 작업은 이력 정책 연결로 한정한다. 드래그/폭 변경/편집 완료당 한 명령으로 그룹화하고 최근 100개를 보관하며 새로고침 시 초기화한다. Undo 이후 새 명령 실행 시 Redo를 제거한다. 출력 모드·선택·확대와 폰트 파일 등록/삭제는 이력에서 제외한다. 실제 폰트 삭제 UI와 실행 경로를 이 단계에서 처음 연결한다. 삭제 직전에 현재 문서 및 Undo/Redo 양쪽 이력의 참조를 모두 검사하고 참조가 없을 때만 삭제한다. system-sans는 항상 삭제를 차단한다.

앱 출력은 편집 확정·폰트 로딩·문서 검증·높이 재측정·다음 프레임 순서를 거친다. 준비 중 문서가 바뀌면 준비 결과를 폐기하고 다시 검증해 오래된 상태로 인쇄하지 않는다. 글씨 포함 준비 실패는 출력을 막고, 빈 모눈은 텍스트 폰트/넘침과 독립적으로 준비한다. Ctrl/Cmd+P는 가로채지 않고 경고는 화면에서만 보인다. 인쇄 진입 시 DOM은 같은 용지를 유지한다.

검증: 100개 이력 경계·새 명령 후 Redo 제거·폰트 변경과 700→400의 원자적 Undo, 현재/Undo/Redo 각각의 폰트 삭제 차단, 이력 만료 후 삭제를 확인한다. 폰트 로딩 도중 편집·조합 중 출력·빈 모눈 출력·Ctrl+P·인쇄 취소와 재편집, 출력 후 원문 유지, 경고/UI/textarea의 미출력을 검사한다.

### U6. 수용 검증과 사용 안내

의존: U5. 대상: `tests/browser/acceptance.spec.ts`, `docs/qa/acceptance.md`, `README.md`.

원본 10절 전체를 수용 체크리스트로 옮긴다. 방향 2 × 간격 4 × 출력 모드 2의 16개 조합을 Chrome/Edge 각각 PDF로 확인한다. 여백 0/5/20mm·강조선 0/5/10·1mm 얇고 연한 선은 별도 경계 사례로 둔다. 서로 다른 글꼴·색의 텍스트 2개를 배치·폭 조절하고 저장 복원 후 글씨 포함/빈 모눈을 전환한다. 시스템 폰트만 있는 최초 상태도 별도 검사한다.

형식·타입 검사와 관련 단위/브라우저 검사를 실행하고 결과를 기록한다. PDF는 페이지 수·A4 치수·간격·줄바꿈·폰트·좌표를 확인한다. 실제 프린터가 있으면 100%에서 100mm를 측정하고 기종/설정/오차를 기록한다. 없으면 실물 미검증이라고 표시한다. README에는 실행 방법, 인쇄 설정, 자동 저장 한계, 업로드 권한, 시스템 폰트의 기기별 차이와 Ctrl+P 제한을 안내한다.

## 위험과 검증 경계

- 단일 페이지 완화는 U1의 실측 결정이다. 본체 CSS가 바뀌면 해당 인쇄 사례를 다시 검증한다.
- FontFace 성공만으로 한글 전체 글리프나 PDF 글꼴 임베드를 보장하지 않는다. 테스트 문구 미리보기와 실제 PDF 검사를 별도로 수행한다.
- 실제 인쇄 대화상자·한글 IME·실물 출력은 자동 검사 통과와 구분해 기록한다. 확인하지 않은 브라우저/장비의 결과를 추정해 통과로 쓰지 않는다.
- 테스트 도구는 구현 착수 시 사용 가능한 환경을 확인해 선정한다. 단위 검사는 Vitest, 브라우저 검사는 Playwright를 계획 후보로 두며 설치/실행 불가 시 동등한 검증 수단과 미검증 범위를 기록한다.

## 계획 검토 및 실행 경계

각 단위는 원본의 해당 절에 추적 가능하며 출력 검증을 첫 선행 조건으로 유지한다. 원본의 제외 범위, 데이터 모델 version 1, 브라우저 인쇄 경로를 확장하지 않는다. 이 문서 작성 시점에는 앱 코드·테스트 실행·브라우저 출력 검증을 수행하지 않았다. 계획 검토 후 실행을 시작하면 버전 관리 준비와 기존 문서 첫 커밋을 마친 뒤 U1부터 진행한다. 각 단위의 완료에는 공통 커밋 조건을 적용한다.
