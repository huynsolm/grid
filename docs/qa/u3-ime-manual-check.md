# U3 실제 한글 IME 사용자 확인

상태: **사용자 확인 대기**. 조합 이벤트를 흉내 낸 자동 검사는 보조 수단이며 실제 Windows 한글 입력기 검증을 대신하지 않는다. 확인 전 U4로 진행하지 않는다.

## 준비

1. [편집 화면](http://127.0.0.1:5173/)을 실제 Chrome과 Edge에서 각각 연다.
2. 사용 중인 OS·브라우저 버전·한글 입력기 이름을 아래에 기록한다.
3. ‘글상자 추가’ → 용지의 글상자를 더블클릭하거나 선택 후 Enter로 직접 편집을 시작한다. 오른쪽 ‘내용’ 입력창에서도 같은 입력을 확인한다.
4. 화면 확대 50/100/200%를 바꾸어 확인한다. 조합 중인 글자는 입력기의 밑줄/조합 표시로 구분한다.

현재는 저장 기능이 없으므로 작업 내용은 새로고침하면 사라진다. 테스트 문구는 필요하면 별도로 복사해 둔다.

## 체크리스트 — 브라우저별로 확인

| 항목 | 사용자 동작과 기대 결과 | Chrome | Edge |
| --- | --- | --- | --- |
| 조합과 확정 | ‘한글 입력 확인’을 천천히 입력한다. 조합 중 글자가 사라지거나 중복되지 않고, 조합 확정 후 마지막 글자가 정확히 남는다. | 대기 | 대기 |
| 개행·빈 줄 | 조합을 먼저 확정한 뒤 Enter로 개행하고 빈 줄을 하나 만든다. 본문·입력창·용지의 개행과 빈 줄이 일치한다. 끝에도 빈 줄을 넣어 확인한다. | 대기 | 대기 |
| 기본 삭제 키 | 조합 중 Backspace/Delete로 글자를 고친다. 입력기 본래 동작을 유지하고 글상자 자체가 삭제되지 않는다. 입력창 안 Ctrl/Cmd+Z는 브라우저 기본 편집 동작을 유지한다. | 대기 | 대기 |
| 조합 중 앱 동작 | 미확정 글자가 있을 때 다른 글상자·속성·용지를 클릭하거나 드래그, 삭제 버튼을 시도한다. 앱이 임의 확정·이동·항목 삭제를 수행하지 않고 조합 내용이 유지되어야 한다. | 대기 | 대기 |
| 조합 중 완료 키 | 조합 중 Ctrl/Cmd+Enter가 앱의 편집 완료로 넘어가거나 조합 글자를 잃게 하지 않는다. 조합을 확정한 후 Ctrl/Cmd+Enter를 누르면 한 번 완료된다. 입력기 자체의 확정 동작과 앱 완료를 구분한다. | 대기 | 대기 |
| 완료 후 재편집 | Ctrl/Cmd+Enter로 완료한 뒤 더블클릭/선택 후 Enter로 다시 연다. 마지막 한글·개행·빈 줄이 동일하다. | 대기 | 대기 |
| 편집 취소 | 조합을 확정한 후 내용을 고치고 Esc로 취소한다. 편집 시작 전 내용으로 돌아온다. 조합 중 Esc는 입력기 본래 동작을 우선하므로 같은 것으로 간주하지 않는다. | 대기 | 대기 |
| 확정 후 이동·폭 | 조합과 편집을 완료한 뒤 글상자를 드래그하고 오른쪽 녹색 핸들로 폭을 조절한다. 조합 텍스트가 보존되고 폭에 맞춰 자동으로 줄바꿈한다. 세로 핸들/글자 자동 축소는 없다. | 대기 | 대기 |
| 확대와 경계 | 50/100/200%에서 같은 글의 높이·안전 영역 판단이 같고, 정상 글상자는 안전 영역 밖으로 끌려가지 않는다. Alt+드래그는 임시 스냅 해제다. | 대기 | 대기 |
| 출력 모드 복귀 | 빈 모눈으로 바꿨다가 글씨 포함으로 돌아온다. 원문이 남고 높이·넘침 상태가 다시 계산된다. 방향/여백 변경 시 영역 밖 글은 자동 이동하지 않고 경고한다. | 대기 | 대기 |

조합 중 OS/입력기의 동작 차이로 기대 결과와 다르면 ‘정상’으로 처리하지 말고 단계와 실제 결과를 기록한다. 자동 검사 통과를 이 표의 사용자 통과로 복사하지 않는다.
