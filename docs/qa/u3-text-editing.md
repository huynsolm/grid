# U3 텍스트 편집 검증

검증일: 2026-10-21

상태: **자동 검증 완료, IME 사용자 확인 대기**. 실제 한글 입력기는 [사용자 체크리스트](u3-ime-manual-check.md)로 확인해야 한다. U4는 착수하지 않았다. 자동 조합 이벤트 검사를 실제 IME 통과로 기록하지 않는다.

## 구현 범위

- 글상자 추가·복제·삭제·선택, 단일 클릭 선택, 더블클릭/선택 후 Enter로 직접 편집을 제공한다.
- 드래그 이동과 오른쪽 핸들의 가로 폭 조절, 자동 높이를 사용한다. 세로 핸들·자동 글자 축소·화면의 임의 콘텐츠 잘림은 추가하지 않았다.
- 내용·6~200pt 크기·HEX 색·정렬·줄 간격 1~3·시스템 글꼴 굵기 400/700·x/y/폭 mm 속성을 제공한다. 글꼴은 시스템 기본이며 문서용 폰트 업로드는 구현하지 않았다.
- 변경은 U2 명령 경로를 사용한다. 입력·이동·폭 조절의 초안은 `src/editor/session.ts`의 분리된 런타임 객체에만 반영한다. 확정 시 하나의 update-item 명령과 해당 작업의 groupId를 전달한다. Esc/포인터 취소는 문서를 바꾸지 않는다. 추가/복제/삭제도 명령으로만 변경한다.
- `src/state/app-document.ts`는 UI를 다시 실행하지 않고 동일 저장소를 참조하는 단일 문서 모듈이다. 브라우저 테스트도 이 저장소를 구독해 실제 변경 전후 값·명령·groupId를 확인한다. 테스트용 window 기록은 테스트에서만 생성하며 제품에 전역 테스트 훅을 추가하지 않았다.

## 계산·입력 규칙

- `src/editor/geometry.ts`: 안전 영역 원점 기준 최근접 위치 스냅, 최소 10mm 및 격자 배수의 폭, Alt 임시 해제, 안전 영역 제한을 DOM 없이 계산한다. 숫자 속성 입력은 스냅하지 않으며 모델의 범위 검증을 적용한다.
- 정상 항목의 이동은 공통 측정 높이를 사용해 안전 영역 안으로 제한한다. 경계 제한 후에도 스냅 위치는 격자 배수로 유지한다. 처음부터 영역 밖인 항목은 방향/여백 변경만으로 재배치·축소하지 않고 경고한다.
- `src/editor/measure.ts`: offsetHeight를 25.4/96으로 mm 환산한다. 남은 영역과 높이의 차이가 1 CSS px 이내인 경우에만 rect.height/외부 확대 배율로 정밀 재확인한다. 넘침 판정과 드래그 제한이 이 함수를 공유한다. 측정 입력은 작은 인터페이스로 추상화해 DOM 없이 분기와 수치를 검사한다.
- 빈 모눈 모드에서는 텍스트 높이 측정을 생략하고 예전 높이를 사용하지 않는다. 글씨 포함 복귀 시 현재 표시 div를 다시 측정한다. 빈 모눈 출력 가능 상태는 텍스트 넘침과 독립적이다.
- `src/editor/text-style.ts`가 용지 표시 div와 직접 편집 textarea의 위치·폭·폰트·굵기·크기·색·정렬·줄 간격·padding 0·border 0·box-sizing·white-space/overflow-wrap/word-break·자간 0을 동일하게 적용한다. 속성 패널의 내용창은 종이 위 편집 오버레이와 구분한다.
- 텍스트는 textContent로 표시하고 붙여넣기는 text/plain만 사용한다. 끝의 개행도 빈 줄 높이로 남도록 실제 문서 div의 정적 CSS 의사 요소로 마지막 줄을 보존한다. 사용자 HTML을 삽입하지 않으며 문서 text 값 자체도 변경하지 않는다.
- compositionstart~compositionend 중 앱의 이동·삭제·확정을 막고 textarea의 본래 조합·삭제·개행 키 처리는 유지한다. Ctrl/Cmd+Enter는 조합 종료 후 완료, Enter는 개행, Esc는 조합 밖에서 초안 취소다. 입력창 안의 편집 단축키는 브라우저에 맡긴다. 입력창 밖 Undo/Redo 키는 분류·기본 동작 방지만 하며 이력 실행은 없다.

## 출력 상태와 범위 경계

`#editor-state`에 아래 상태를 노출한다.

| 속성 | 값과 의미 |
| --- | --- |
| data-with-text-allowed | true: 현재 내용이 안전 영역 안, false: 넘침, unknown: 빈 모눈 등으로 재측정 대기 |
| data-grid-only-allowed | true: 텍스트 넘침과 관계없이 빈 모눈 가능 |
| data-measured | 현재 표시 div를 측정했는지 여부 |
| data-shortcut | 입력창 밖에서 분류한 undo/redo. 실제 이력 동작은 아님 |

넘침 항목에는 data-overflow가 붙고 화면에 경고한다. **이 상태를 실제 출력 버튼 차단과 연결하지 않았다.** U5의 출력 준비/차단을 구현한 것으로 간주하지 않는다. 기존 폰트 준비 상태와 런타임 초안의 재그리기 revision을 분리해 편집 재그리기가 기존 버튼 준비 상태를 영구 대기로 만들지 않도록 했다.

저장·복원·문서 폰트 업로드·Undo/Redo 정책은 추가하지 않았다. 현재 문서는 메모리에만 있으며 새로고침 시 초기화된다. 기존 U1 검증 경로의 테스트 폰트 기능은 보존했지만 편집기 문서의 업로드 기능으로 확장하지 않았다.

## 실행한 검사

| 검사 | 실행 | 결과 |

| 형식 | npm run check:format:u3 | 통과. U3 소스/테스트 대상 Prettier 검사 |
| 타입·빌드 | npm run build | TypeScript strict 검사 및 Vite 배포 빌드 통과 |
| 단위 | npm run test:unit | **50개 통과**: 기존 34개 + U3 16개 |

U3 단위 검사: 스냅 반올림, 최소 폭·격자 배수, Alt/숫자 입력 예외, 안전 경계, 측정의 경계 분기와 배율 제거, 측정 불가, 초안 분리·명령 생성·그룹 유지/분리다.

U3 브라우저 시나리오는 각 브라우저에서 13개다(기존 U1/U2 8개 포함 총 21개).

- 각 편집 동작의 명령 경유, 초안 동안 문서 미반영, 확정 시 전후 값·groupId, 취소 시 명령 없음.
- 단일 선택·더블클릭/Enter 편집·Ctrl/Cmd+Enter 완료, 추가·복제·삭제.
- 숫자 스냅 예외·최소 폭 검증·속성 초안 취소·굵기/색/정렬/줄 간격 적용.
- 50/100/200%에서 같은 mm 이동·폭 조절·높이·안전 경계, 포인터가 경계를 넘어가도 안전 영역 내 제한, Alt 스냅 해제와 Esc 취소.
- 합성 composition 이벤트 중 앱 확정·삭제·포인터 시작 차단과 조합 후 확정. 네이티브 IME 검증과 구분한다.
- 긴 한글/영문·빈 줄·끝의 개행, HTML 붙여넣기의 일반 텍스트 처리와 비실행, 표시 div/textarea 스타일 일치.
- 입력창 안/밖 단축키 구분, 넘침 false 상태에서도 기존 인쇄 버튼 차단 연결 없음, 빈 모눈 허용과 글씨 포함 복귀 재측정, 여백·폰트 크기 변경 후 재검증.
- 방향 변경 시 좌표 보존·경고, print 매체에서 textarea·핸들·경고 미출력과 표시 텍스트 유지.

## 인쇄 CSS와 화면 확인

`src/paper/paper.css`, `src/print/print.css`는 **변경하지 않았다**. 새 `src/editor/editor.css`는 편집기 배치·선택 프레임·직접 입력 오버레이·실제 문서의 끝 빈 줄 보존만 담당한다. 편집 오버레이·속성 패널·핸들·상태/경고는 기존 screen-only 규칙으로 인쇄에서 제외한다. 인쇄용 텍스트를 복제하거나 다른 엔진으로 재레이아웃하지 않는다.

기본 편집·초안 편집·인쇄 매체 스크린샷을 직접 확인했다. 증거는 `docs/qa/tmp/u3-text-screen.png`, `u3-text-draft.png`, `u3-print-media.png`다. U1 검증 경로를 같은 Chromium·뷰포트에서 캡처한 `u3-u1-regression-chromium.png`는 기존 U1 인쇄 매체 화면과 픽셀이 일치했다(`u3-u1-regression.json`). 이것은 편집기 실제 PDF/실물 프린터를 검증했다는 뜻은 아니며 최종 실제 출력 수용 검사는 U6에 남는다.

## 남은 위험·미확인

- **실제 한글 IME 사용자 확인 대기**: 조합 확정·개행·삭제·조합 중 클릭/드래그, 직접 입력과 속성 내용창을 Chrome/Edge에서 확인해야 한다. 체크리스트의 결과는 모두 대기다.
- 저장이 없으므로 새로고침 시 내용이 사라진다. U4를 시작하거나 구현했다고 기록하지 않는다.
- Undo/Redo 실행과 넘침 시 실제 출력 차단은 U5 범위다. 현재의 가능 여부 표시는 상태 안내이며 출력 안전 게이트가 아니다.
- 편집한 내용의 실제 PDF·실물 프린터 차이, OS별 IME 차이는 자동 검사만으로 보장하지 않는다.

커밋은 U3 구현/자동 검사 결과 보존용이며 상태는 **자동 검증 완료, IME 사용자 확인 대기**다. 사용자 확인이 끝나기 전 U4로 넘어가지 않는다.
