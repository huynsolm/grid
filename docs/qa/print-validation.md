# U1 인쇄 검증 기록

기록일: 2026-10-20 / 재판정일: 2026-10-21 (Asia/Seoul)

상태: **Chrome·Edge 수신 파일 각각 정량 통과, 육안 확인 및 나머지 필수 사례 대기**. U1은 미완료이며 **U2 진입 금지**를 유지한다. 2026-10-21 기준 변경 후 두 파일을 재판정했다. 기존 0.1mm 용지 치수 기준의 실패 기록은 아래 이력에 보존한다. 전체 인쇄 설정·여백 5mm(추정)의 사용자 확인과 가로·여백 0/20mm·빈 모눈·업로드 폰트 등 나머지 필수 사례 검증은 계속 대기한다. 에이전트의 렌더링 확인만으로 사용자 육안 확인 및 전체 수용 검증을 완료 처리하지 않는다.

## 기준 변경 이력 — 2026-10-21

사용자 요청에 따라 용지 크기(MediaBox 환산·회전 반영)의 축별 절대 오차는 **0.2mm 이하**, 100mm 기준선 길이 오차는 기존 **0.1mm 이하**, 페이지 수는 **1**로 분리한다. 앱의 A4 210×297mm/297×210mm와 내부 mm 배율, 모눈선 굵기·래퍼 미세 여유 범위 등 설계 수치는 그대로다. 이 변경은 PDF 측정 판정에만 적용한다.

**원인 추정:** Chrome·Edge의 공통 Chromium/Skia 출력에서 관측된 MediaBox는 594.95996×841.91998pt다. 각각 2479/300인치와 3508/300인치를 pt로 바꾼 594.96×841.92pt에 거의 일치한다. 1/300인치(약 0.084667mm) 단위의 용지 치수 양자화/반올림으로 추정하지만, 브라우저 내부에서 그 과정을 수행한다는 원인은 확정하지 않았다. 100mm 기준선이 99.998317mm라는 별도 측정은 콘텐츠 축소의 증거가 없음을 뒷받침한다. 0.111mm 오차는 단일 1/300인치 단위보다 크므로 단순 최근접 반올림 한 번으로 설명된다고 단정하지 않는다.

**완화 근거:** 용지 치수 메타데이터의 출력 반올림 가능성과 콘텐츠 배율 검사를 구분한다. 실물 프린터에서는 용지 이송·정합에 따라 0.2mm보다 훨씬 큰 mm 단위 위치 오차/보정이 필요할 수 있다. 예를 들어 [Canon 공식 인쇄 위치 조정 안내](https://oip.manual.canon/USRMA-8527-zz-SSS-730-enGB/contents/devu-mainte-prt_finish_quality-ajst_prtposi.html)는 세로 3.5mm·가로 1.5mm 보정 사례를 든다. 이는 모든 프린터의 오차 하한이나 본 프로젝트 프린터의 실측값이 아니며, 실물 검증은 계속 별도다. 따라서 용지 기준만 0.2mm로 완화하고 실제 모눈/콘텐츠 배율을 검사하는 기준선은 0.1mm로 유지한다.

측정 단위 테스트 10개를 실행해 모두 통과했다. 두 수신 파일은 새 기준으로 정량 통과다. 이전 0.1mm 기준의 실패 판정은 수신 이력과 legacy JSON에 남긴다. `margin5`는 위치에서 추정한 값이며 사용자 확인 전까지 **추정** 표시를 유지한다. 가로·여백 0/20mm·빈 모눈·업로드 폰트, 사용자 육안 및 환경/설정 확인은 대기 중이다. **U1 미완료, U2 진입 금지**를 유지한다.

- 세로/가로 A4, 안전 여백 0/5/20mm, 글씨 포함/빈 모눈, 화면 확대 50/75/100/200%.

## 사용자 저장 절차

수행 주체는 **사용자**다. Chrome·Edge에서 각각 [미리보기](http://127.0.0.1:5173/)를 열어 설정을 선택하고 앱 출력 버튼으로 실제 인쇄 대화상자를 연다.

1. PDF로 저장, A4, 선택 방향, 인쇄 배율 100%, 추가 여백 없음, 페이지 맞춤 해제, 머리글/바닥글 해제를 확인한다.
2. `docs/qa/pdfs/u1/`에 저장한다. 디렉터리는 로컬에 준비하며 PDF는 Git에서 제외된다.
3. 파일명: `{browser}-{orientation}-margin{mm}-{case}-r{run}.pdf`. browser는 chrome/edge, orientation은 portrait/landscape, case는 system-with-text / system-grid-only / upload-with-text, run은 재검증 번호(초기 1)다. 예: `chrome-portrait-margin5-system-with-text-r1.pdf`.
4. 브라우저 전체 버전·OS 버전·화면 확대 배율·인쇄 배율·A4/방향·여백·머리글/바닥글·페이지 맞춤 설정을 사례별로 기록한다. 같은 환경이면 환경 id로 묶되 달라진 설정은 별도로 적는다.
5. 화면과 PDF의 줄 수·줄바꿈 위치·글꼴·좌표를 육안 대조한다. 하단 글자/선, UI/경고 미출력, 인쇄 취소 후 화면 유지도 확인한다.
6. 파일을 위 경로에 두거나 이 채팅에 제공하고 환경/설정과 육안 결과를 알려 준다. **결과 제공 전에는 U1 대기이며 U2로 진행하지 않는다.**

빈 모눈 사례에는 텍스트가 숨겨지고 검증 기준선만 모눈과 함께 남아야 한다. 검증 브라우저 선택은 파일명 안내용이며 실제 브라우저를 바꾸지 않는다. OS 브라우저 확대는 100%로 두고 화면 내부 확대는 75% 기본으로 시작한다.

## 정량 측정 절차

수행 주체는 에이전트다. 도구는 `pdfplumber==0.11.9`이며 `scripts/qa/measure_pdf.py`를 사용한다. ReportLab은 알려진 PDF를 만드는 측정 단위 테스트 전용이며 앱에는 포함되지 않는다.

```powershell
python -m pip install -r requirements-qa.txt
python scripts/qa/measure_pdf.py docs/qa/pdfs/u1/chrome-portrait-margin5-system-with-text-r1.pdf --orientation portrait --output docs/qa/tmp/chrome-portrait-margin5-system-with-text-r1.json
```

1. 페이지 수·원본 MediaBox·UserUnit(없으면 1)·회전을 읽는다. MediaBox 축 길이를 회전 90/270도에서 바꾸고 UserUnit × 25.4/72로 mm 환산한다. 세로 210×297mm / 가로 297×210mm 각각의 축 오차를 계산한다.
2. PDF 선분/경로 중 RGB #d00000의 직선 기준선 하나를 찾는다. 변환된 중심선 양 끝점의 거리를 UserUnit × 25.4/72로 mm 환산한다. 선 굵기 바깥쪽을 측정하지 않는다. PDF 파서의 끝점은 회전 반영된 좌표다.
3. 페이지 수 1, 회전 반영 두 축 용지 치수 오차 각각 ≤0.2mm, 기준선의 |길이−100mm| ≤0.1mm여야 정량 통과다. 기준선이 없거나 래스터화/중복/식별 불가이면 미검증이다. 차원/길이 실패와 누락이 함께 있으면 실패를 우선한다.
4. JSON 값과 아래 사례별 결과를 문서에 기록한다. 정량 통과는 사용자 대화상자 저장 확인·시각 검증을 포함하지 않는다. 파서/브라우저/파일이 없으면 미검증이며 U1 완료로 선언하지 않는다.

## 채택 CSS와 미세 여유

현재 후보는 `src/print/print.css`의 여백·외부 레이아웃 초기화, transform 제거, 래퍼 overflow:hidden·break-inside:avoid·break-after:avoid다. 용지 내부 치수는 원본 A4 그대로다. 미세 여유는 **0mm**다. 실제 PDF의 빈 추가 페이지가 재현된 경우에만 최대 0.1mm 범위에서 검토하며 하단 잘림 또는 배율 변화가 생기면 통과시키지 않는다. 아직 실제 PDF 기준으로 채택 확정한 설정은 없다.

## 자동 검사 및 화면 점검

- 타입 검사와 배포 빌드 통과.
- 브라우저 자동 검사 18개 통과: Chromium 156.0.8078.4 / Chrome 155.0.8059.80 / Edge 155.0.4283.62. 6개 시나리오를 각 브라우저에서 실행했다. 용지 DOM 유지·인쇄 UI 숨김·기준선 길이 속성·출력 모드·잘못된 폰트 처리·방향/여백 조합의 고정 CSS 치수를 확인했다.
- PDF 측정 단위 검사 **10개 통과(2026-10-21)**. 최초 7개에 폭 오차 0.111mm 통과·0.25mm 실패·기준선 오차 0.11mm 실패의 경계 사례 3개를 추가했다. 기존 검사: 정상 치수·치수 오류·기준선 길이 오류·기준선 누락·복수 페이지·가로/회전·UserUnit 처리. 테스트용 PDF는 임시 폴더에 생성 후 제거하며 수동 증거로 사용하지 않는다.
- 화면과 print 매체의 스크린샷을 직접 확인했다. 로컬 증거 `docs/qa/tmp/u1-screen.png`, `docs/qa/tmp/u1-print-media.png`는 Git에서 제외된다. 이것으로 페이지 수나 실제 PDF의 글꼴/줄바꿈을 판정하지 않는다.
- Python 검사는 Codex 번들 Python 3.12.14 환경의 pdfplumber 0.11.9 / ReportLab 4.4.9를 사용했다. 기본 Python 3.14에는 QA 의존성이 없으므로 README 설치 절차를 따라야 한다.

## 완료 조건

페이지 수 1·용지 축별 오차 ≤0.2mm·100mm 기준선 오차 ≤0.1mm를 만족하는 필수 사용자 PDF와 환경 정보가 제공되고 육안 검증까지 통과한 뒤 해당 결과와 U1 완료 커밋을 기록한다. 현재 커밋은 준비 코드 저장용이며 U1 완료 커밋이 아니다. 실물 프린터는 별도 미검증이다. PDF 원본은 로컬 보관하며 저장소 복제만으로 복원되지 않는다.
